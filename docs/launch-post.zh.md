## 版本 A · 主贴（即刻 / 朋友圈 / 微信群 / 知乎想法，约 550 字）

**我给自家孩子做了一个 B 站学习面板，装在自己电脑的侧栏里**

孩子看 B 站这件事，我一直有两件事不舒服：一是推荐流会把「随便看看」变成「一直看下去」；二是看完了，我并不知道他看进去多少。

所以我没有做推荐算法，也没做题库生成器。我做的是一台「排课 + 打卡 + 判分 + 奖励」的机器，装在 DeepSeek Harness 桌面端的侧栏里：

1. **家长挑片**：粘一个 BV 号或整条链接就入库，分类、最低年龄、为什么选它，都是我自己填的。
2. **按周排课**：一键把一周排满，按分类轮转、跳过失效片子、跳过最近三周排过的；不合适的手动换。
3. **孩子打勾**：看完点一下，本周条数、连续打卡、近 7 天柱状图都会动。
4. **配一套课卡**：一条片子一套卡，3 到 8 题，题目我自己写（不给 AI 代写，避免给孩子出我没把握的题）。
5. **交卷判分**：答满 80 分当天给一个盲盒，抽到东西进奖品墙。
6. **错题回炉**：答错的题自动进错题本，点选项当场重做，答对才算「已掌握」。
7. **勋章**：8 枚按门槛自动发放，没到门槛就显示还差多少。

还有一件事我特意做了：**家长锁**。四位 PIN，锁住「奖品池 / 勋章门槛 / 每天几条」这些设置，孩子点开设置先要输 PIN，解锁记 30 分钟。它不是加密，挡的是「随手改奖励」，不是「懂电脑的人」，这点我写在 README 里了。

数据全部在这台机器上（`~/.dsh/bili-lesson/` 十来个 JSON），没有云同步、没有遥测；出站只请求 B 站的视频信息和封面，不抓弹幕、不代理播放、不碰账号 Cookie。代码 MIT 开源，85 条自测全绿。

它不替你做家长，只是把「你今天该看哪条」和「你看进去多少」变成看得见的东西。

https://github.com/liweitan2046-cyber/dsh-bili-lesson

## 版本 D · 技术社区（V2EX / 掘金 / 少数派，约 450 字）

**做了一个 DSH 插件：把 B 站变成家里的「课程表 + 打卡 + 判分」机器**

背景：想让孩子看经过挑选的科普片，而不是推荐流。于是按 DeepSeek Harness 的插件规范写了一个侧栏面板（cordis patch + 客户端 `__ModuleLoader__` 工厂，服务端注册 `/bili-lesson/*` 路由）。

几个实现上的取舍，可能对写同类插件的人有用：

- **数据就是一个目录里的 JSON**：`videos / plans / watch / lessons / settings / attempts / mistakes / rewards / honors / prizes / medals`，写盘 tmp + rename，半截文件当空读，坏文件不会让面板打不开。
- **排片是纯函数**：分类桶轮转、跳过失效片与最近三周排过的，服务端只归一化不写盘，写盘只发生在用户点「自动排这一周」。
- **课卡与错题是一套数据契约**：`lessonId:qid` 做 key，掌握状态单独存 `mistakes.json`，交卷只追加 `attempts.json`，不回头改历史。
- **家长锁是软锁**：PIN 加盐 sha256 + `sessionStorage` 30 分钟，README 里明说它挡不住会改文件的人。
- **自测真的起 HTTP 服务**：`npm test` 跑 85 条，其中一条会真的请求一次 B 站 view 接口（aid → bvid 映射），所以断网时会失败，这是刻意的。

依赖只有 react（peer）+ DSH 注入的 client runtime；Node 24。MIT。

https://github.com/liweitan2046-cyber/dsh-bili-lesson

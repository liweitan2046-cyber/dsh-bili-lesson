# 片源与题目：数据是你喂进去的

这个插件不内置搜索、也不生成题目，所以「片子从哪来」「题目怎么写」是使用它最费时间的两步。
这份文档把这两件事讲到能照做为止，包括接口、字段、上限和会踩的坑。

---

## 0. 一句话流程

```
找片（B 站站内搜 / AI 助手 / 别处拷）→ 粘 BV 号入库 → 填分类·年龄·理由
   → 一键排本周 → 孩子看完打勾 → 给这条片写 3–8 道题 → 交卷判分 → 错题回炉
```

排课与判分是机器干的；**挑片和出题是家长干的**，插件只保证这两步的数据结构不出错。

---

## 1. 片子怎么调取

### 1.1 手动入库（最常用）

在「片库仓库」顶部粘一个 **BV 号**或**整条 B 站链接**（手机 App 复制的分享文案也行），回车。

服务端只做一件事：用 B 站的公开只读接口拉元数据

```
GET https://api.bilibili.com/x/web-interface/view?bvid=<BV 号>
referer: https://www.bilibili.com/
```

不带 Cookie、不登录、不抓弹幕、不代理播放流。返回后由插件落这些字段（见 `src/bili.js:20` 与 `src/routes.js:296-313`）：

| 字段 | 来源 | 说明 |
|---|---|---|
| `bvid` / `id` | 你粘的那串 | 片库的 key |
| `title` `cover` `duration` `owner` | view 接口 | 封面强制 https（`http://` 会被改写成 `https://`） |
| `category` | 你填 | 默认「未分类」；排片和星图都按它分组 |
| `minAge` | 你填 | 默认取设置里的默认年龄（出厂 6） |
| `reason` | 你填 | 「为什么给你看这条」——写在卡片上，孩子看得见 |
| `caution` | 你填 | 「看的时候注意什么」，同样显示给孩子 |
| `dead` | 探测结果 | 接口返回 `code != 0`（下架/私密）则标 true，但**不自动删**你的条目 |

接口连不上是 502，视频不可用是「dead」而不是报错——两种情况都不会让你填的分类和理由丢失。

### 1.2 批量入库

如果一次要加十几条，直接改数据文件更快。`~/.dsh/bili-lesson/videos.json` 是个以 BV 号为 key 的对象：

```json
{
  "BV11CA3zYEJ3": {
    "id": "BV11CA3zYEJ3",
    "bvid": "BV11CA3zYEJ3",
    "title": "数字启蒙儿歌 1 到 10",
    "cover": "https://i0.hdslb.com/bfs/archive/....jpg",
    "duration": 504,
    "owner": "某某儿歌",
    "category": "数学",
    "minAge": 3,
    "reason": "唱到 10，节奏慢，适合跟读",
    "caution": "",
    "dead": false,
    "addedAt": 1794700000000,
    "checkedAt": 1794700000000
  }
}
```

只填 `bvid` + `category` 也能用：下次在面板里点这条卡片的「探活」或重进片库，标题封面会被补全。

### 1.3 找片：为什么没有内置搜索

B 站的搜索接口要 **wbi 签名**（`/x/web-interface/wbi/search/type`），直接 GET 一律 **HTTP 412**，签名算法会变、还有风控，
放进一个给孩子用的本地插件里不划算。所以找片放在插件外面，三条现成的路：

1. **站内搜完复制链接**：B 站网页/App 搜「恐龙 儿童科普」，挑好点分享复制链接，粘回面板。
2. **让 AI 助手帮你列一批**：把需求说清（年龄、主题、时长上限），让助手给出片名 + BV 号；你复核后批量粘。
   实测可用的是第三方数据接口（例如 TikHub 的 `bilibili/app/fetch_search_by_type`，给 keyword 返回一批视频，
   **只有 aid 没有 bvid**，再用 `api.bilibili.com/x/web-interface/view?aid=<aid>` 换到 bvid）。
3. **从收藏夹/别处拷贝**：把 `videos.json` 的结构复制过去，只要 `bvid` 对得上就能接管。

> 无论哪条路，**最后一步都是家长过一遍**：分类、最低年龄、理由由你填，插件不会替你判断「这条适不适合我孩子」。

### 1.4 探活（片子还在不在）

片库右上角「校验失效」→ `POST /bili-lesson/videos/refresh`：一次最多 30 条，每条之间 sleep 350ms（不把 B 站当靶子），
返回 `{checked, dead, remaining}`，多余的留到下一次点。下架的标 `dead: true`，排片时自动跳过，条目留在片上让你自己决定删不删。

## 2. 一周怎么排

点「自动排这一周」→ `POST /bili-lesson/plan/auto`，规则（`src/plan.js`）：

- 按**分类桶轮转**：建桶 → 桶按当前条数降序 → 依次取，保证同一个分类不会连着堆满一周；
- 跳过 `dead` 的片子；跳过**最近三周排过**的（`recentIds`），避免反复给孩子看同一条；
- 每天条数 = 设置里的「每天几条」（`perDay`，1–6），周一开头、排满为止；片子不够就留空，不会凑数。

结果写进 `plans.json`，key 是**周一日期**（例如 `"2026-11-16"`）：

```json
{ "2026-11-16": { "days": { "0": ["BV11CA3zYEJ3"], "1": ["BV1ojGGzVEkz"], ... } } }
```

注意：`GET /plan` **只归一化不写盘**，所以新的一周第一次打开时航线是空的——这是设计，不是 bug；点一下「自动排这一周」才落盘。

## 3. 题目怎么写

在「课卡工坊」选一条片子 → 写题干、点圆圈选正确项、填提示与解释 → 保存。一条片子一套卡，**3–8 道题**。

### 3.1 字段语义（`src/lesson.js:15-35`）

| 字段 | 必填 | 语义与上限 |
|---|---|---|
| `prompt` | 是 | 屏幕上的题干；**空题干的题会被丢掉**，全空则保存失败（400） |
| `spokenPrompt` | 否 | 口语版题干（「一后面是几呀？」）；不填就复制 `prompt` |
| `options` | 是（≥2） | 最多 6 个；少于 2 个会被替换成 `["对","不对"]`——**这是个静默兜底，别依赖它** |
| `answer` | 是 | 正确项的**下标**（从 0 开始）；不是整数或越界就落回 0 |
| `hint` | 否 | 答错时显示的一句话（别直接给答案） |
| `explanation` | 否 | 答对后显示的一句强化 |
| `difficulty` | 否 | 1–3，超出会被夹回区间 |
| `variant` | 否 | 同题的不同问法编号，默认 0 |
| `mode` | 固定 | `choice`，目前只有单选题型 |

### 3.2 三条写作原则

1. **一题只考一个点**：「1 后面是几」就只考顺序，别把颜色和数字混在一题里。
2. **选项要等长同构**：三个选项都是单个数字（`2 / 3 / 5`），别出现「`2` / `三个` / `1 后面就是 2 呀`」——后者等于把答案念出来。
3. **干扰项来自片子里真会混的点**：孩子容易把 6 和 9 弄反，就用 `6 / 9` 做干扰项，而不是随手写个 100。

### 3.3 一个真实例子

```json
{
  "id": "ls_e54a088b",
  "videoId": "BV11CA3zYEJ3",
  "topic": "数数：1 到 10",
  "questions": [
    {
      "id": "q1",
      "prompt": "唱数字歌的时候，1 后面是几？",
      "spokenPrompt": "一后面是几呀？",
      "options": ["2", "3", "5"],
      "answer": 0,
      "hint": "一二三，二在一下面",
      "explanation": "1 后面就是 2。",
      "difficulty": 1,
      "variant": 1,
      "mode": "choice"
    }
  ]
}
```

判分规则很简单：每题等权，正确率 ×100 取整；**≥80 分当天给一个盲盒**（同一套课卡同一天只给一次）。
答错的题自动进「错题本」，用 `lessonId:qid` 作为 key，掌握状态单独存在 `mistakes.json`，不回改历史交卷记录。

### 3.4 保存时会挡你的三件事

- 第 n 题还没写题干；
- 选项少于 3 个或多于 6 个（界面提示「少一个选项 / 多一个选项」）；
- 某个选项还空着。

## 4. 如果想把「数据源」做成可配置的

现在的数据源是写死的一个函数：`src/bili.js:20` 的 `fetchVideo(bvid)`。要接第三方接口（TikHub、自建代理、公司内网镜像），
只需要在这一处替换，并把配置塞进 `settings.json`：

1. `DEFAULT_SETTINGS`（`src/store.js:22`）加 `apiBase` / `apiKey` 两个字段；
2. `src/routes.js` 的 `GET /settings` 响应里**必须像 `parentPin` 一样脱敏**（只回 `apiKeySet: true`，不回明文）；
3. 「舰桥设置 → 基础设置」加一行输入框 + 一个「测试连接」按钮（现有 `POST /settings/pin` 是同类写法的先例）；
4. `fetchVideo` 读取配置，失败时回退到官方 view 接口。

风险要写清楚：key 会以明文落在本机 `settings.json`（和现在的 PIN 哈希不同，它是可逆的），
面板一旦被孩子打开且未解锁家长锁，理论上能看到设置页——所以这个开关**默认关闭**，并且也应该受家长锁保护。

## 5. 装完自查

```powershell
npm test              # 85 条自测（会真请求一次 B 站 view 接口，断网会失败）
npm run check:load    # factory id == 包名，服务端/客户端都能加载
```

面板里再确认三件事：片库能加一条、本周能排满、课卡能存下来并在训练舱答一次分。
